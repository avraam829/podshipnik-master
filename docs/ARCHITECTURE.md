# Архитектура
Django 5.2 LTS, Python 3.12, Django ORM, SQLite, серверные HTML-шаблоны и Bootstrap 5.3.3. Приложения catalog/users/cart, отдельный процесс tg_bot. Frontend-сборщик не нужен.

Browser → Django routes → catalog.services → ORM → SQLite.
XLSX → catalog.importing → транзакция → Product/Price/Stock.
Session cart → текущая розничная цена → Order/OrderItem → обработка менеджером.

Product.code — уникальный внутренний ключ; slug сохраняется при создании и не меняется при переименовании. В URL входят обозначение/бренд и обратимо кодированный существующий код, чтобы не склеивать совпадения. search_key — NFKC/casefold без Unicode-пробелов и дефисов, только для поиска. Оригинальный designation сохраняется.

Цена: положительная Price(retail) приоритетнее Product.price; оптовая цена показывается отдельно. Валюта исходного интерфейса RUB; валютного поля/конвертации нет. Порядок выдачи: известная цена → numeric price ASC → отсутствие пробелов → search_key → manufacturer → уникальный code. Цены по запросу в конце. Семейства не моделируются, поэтому глобальная цена соответствует подтверждению владельца.

Stock.amount=9999 — подтверждённая владельцем условная отметка; на сайте «Наличие уточняйте». Остальные положительные свободные остатки показываются после вычета резерва. Из length/width/height нельзя делать d/D/B без подтверждения базы измерения.

Серверная пагинация 24 позиции, поиск и фильтр бренда на сервере; каталог не выгружается целиком в браузер. Подзапросы цены/остатка предотвращают перемножение JOIN. Полнотекстовый contains пока сканирует поисковый ключ; для значительно большего каталога нужен измеренный переход к FTS/PostgreSQL.

Импорт: dry-run по умолчанию. Без кодов разрешена первая загрузка в пустой каталог; точный повтор — no-op. Изменённый файл без кодов в непустую БД отклоняется. Для обновлений используйте экспорт с кодами. Существующие данные автоматически не сливаются и не удаляются. Пустая цена или Excel error сохраняет прежнюю цену с предупреждением для ошибки; для нового товара цена неизвестна. Остальные неверные числовые данные отклоняются до записи. Склад сопоставляется по уникальному точному имени; неоднозначность отклоняется.

Кабинет: профиль с контактами, собственная история заявок и статусами; доступ к чужой заявке возвращает 404. Корзина с количеством 1–9999; добавление, изменение и удаление — POST/CSRF. Checkout перечитывает текущие цены, сохраняет контакты и позиции в транзакции. UUID формы имеет уникальность в БД для защиты от повторной отправки. После записи — redirect на подтверждение.

OrderItem хранит снимок обозначения, внутреннего кода, цены и количества. Для прежних заказов миграция фиксирует сведения, доступные на дату обновления: восстановить утраченную историческую маркировку невозможно. Статусы «Заявка принята», «Подтверждена», «Отменена» меняет менеджер в админке. Платёжный шлюз, email-уведомления и подтверждение email не подключены; заказ хранится в админке и кабинете. Пользователь входит по уникальному логину, email — контактное поле.
